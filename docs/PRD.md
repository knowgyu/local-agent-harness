# Local Agent Harness — 제품 요구사항(PRD)

> 상태: 구현 단계의 요구사항 기준 초안. 설계 검토 전환에서 정한 범위와 수용 기준을 담는다. 구현·지원·검증 완료를 뜻하지 않으며, 아래 미확인 사항은 실제 근거가 생길 때까지 열어 둔다.

Windows에서 AI 에이전트가 개발 시스템과 등록된 작업을 제한된 범위 안에서 사용하도록 돕는 로컬 harness다. Windows에서는 실행 파일을 켜면 로컬 브라우저에 UI가 열리고, 사용자는 그 화면에서 연결 대상과 비밀값을 관리한다. 에이전트는 MCP를 통해 허용된 조회·변경 작업을 수행한다.

핵심 문제는 매번 접속 정보와 실행 방법을 AI에게 따로 알려야 하는 번거로움, 전역 환경변수나 `.env` 파일로 비밀값을 관리하는 불편함, 그리고 로그·Pod 정보 같은 조회 결과에 민감한 값이 섞여 AI 대화로 넘어갈 수 있다는 걱정이다.

제품이 제공할 결과는 다음과 같다.

- 연결 위치와 허용 범위를 한 번 등록하면 에이전트가 대상을 혼동하지 않고 재사용한다.
- 여러 저장소와 임의 이름의 환경을 Jenkins 작업, Harbor 이미지, Dashboard 네임스페이스·Deployment에 연결한 사용자 소유 서비스 묶음을 제공한다.
- 비밀값은 UI에서 만들고 교체하며, 시스템 전체에 환경변수로 등록하지 않아도 된다.
- 사용자가 원하는 환경값은 Windows 현재 사용자 환경변수로 등록·교체·삭제하여 계정의 프로그램에서 사용한다. 서비스 인증용 Credential Manager 보관과는 별도의 사용 경로다.
- 도구 출력은 크기와 범위를 제한하고 민감정보를 가린 뒤 에이전트에 반환한다.
- 사용자가 미리 허용한 서비스 변경과 SSH 작업은 에이전트가 다시 설정을 묻지 않고 수행할 수 있다. 로컬 Python/Docker 실행은 기존 AI 도구에 맡기며 전용 실행기는 필수 기능으로 두지 않는다.
- 기존 저장소와 사용자가 선택한 설정 자료에서 연결 후보를 찾아 근거와 불확실성을 보여주고, 사용자가 검토한 뒤 등록한다.
- 처음 설정하고 연결을 시험하는 과정이 쉬워, 클라이언트별 설정 파일을 직접 편집하는 일을 줄인다.

## 2. 사용자와 사용 환경

주 사용 환경은 Windows 11과 로컬 AI 클라이언트다. Ubuntu에서도 사용할 수 있는 방향을 고려하지만, Windows 11을 우선 플랫폼으로 삼는다. 클라이언트별 MCP 연결 방식과 설치 자동화는 실제 지원 경로를 확인한 뒤 지원 대상으로 확정한다.

여러 환경이나 서비스가 있을 수 있으므로 `dev`/`prod` 같은 고정 프로필을 전제로 하지 않는다. 사용자는 연결 대상과 별도로 서비스 묶음 및 임의 이름의 환경을 만들고, 저장소 하나 이상과 등록된 Jenkins 작업·Harbor 이미지·Dashboard 네임스페이스·Deployment를 연결한다. 연결 대상은 endpoint·인증 참조·허용 범위의 보안 경계로 남으며, 묶음이나 환경 이름이 권한을 넓히지 않는다.

## 3. 대표 사용자 작업

1. GitHub Enterprise의 정확한 API origin, Jenkins, Harbor, Dashboard 기본 주소를 이름 붙은 연결 대상으로 등록하고 연결 테스트를 한다.
2. 여러 저장소와 임의 이름의 환경을 가진 서비스 묶음을 만들고, Jenkins 작업·Harbor 이미지·Dashboard 네임스페이스와 Deployment를 해당 묶음에 연결한다.
3. GitHub 변경 또는 PR 뒤 Jenkins 배포 작업을 실행하고 queue·build·실패 로그의 필요한 구간을 조회한다. 배포 실패 시 Harbor 이미지와 용량, Dashboard의 Deployment·Pod·이벤트·리소스 부족·로그를 이어서 확인한다. 필요하면 사전 허용된 Pod exec 또는 등록 SSH 작업을 실행한다.
4. 로그는 대상·시간·구간을 좁혀 조회하고 필드 축소, 크기·개수 제한, 중복 축소, 등록된 알려진 비밀값 마스킹을 적용한다. 전체 원문을 한 번에 반환하거나 모든 변형 비밀값을 완벽히 찾는다고 약속하지 않는다.
5. AI는 비밀값 없는 카탈로그와 대상별 연결 상태를 조회한다. 설정된 허용 범위에서 일반 변경은 추가 확인 없이 실행하고, 운영 환경 변경 및 삭제·되돌리기 어려운 작업은 매 호출 UI 확인을 받는다.
6. 기존 환경 가져오기에서 선택한 저장소의 Git remote, 사용자가 선택한 문서·Runbook, SSH config 별칭, 기존 연결 설정을 후보로 검토한다. 다른 클라이언트의 대화 전체는 자동으로 읽지 않으며 사용자가 선택한 대화·내보내기 자료만 사용한다.

## 4. 범위와 우선순위

### P0 — 제품의 첫 완성 기준

첫 수직 슬라이스는 Windows 11에서 UI로 비밀값과 대상 하나를 설정하고 MCP 클라이언트에서 읽기 조회를 수행하는 범위다. 실제 회사 접속이 없어도 모의 서비스와 Windows 네이티브 기본 흐름을 검증하면 v0.x 프리릴리스로 전달할 수 있다. 미검증된 회사 연결은 화면과 보고서에 표시한다. 이는 전체 P0 완료나 1.0/운영 검증 완료를 뜻하지 않는다. 전체 P0는 아래 개별 수용 기준으로 판정하며, FR-4의 추가 변경 작업 목록은 확정해야 한다.

MCP 전송은 stdio와 loopback HTTP를 모두 지원하는 제품 요구사항이다. 두 전송의 구현과 검증은 단계적으로 진행할 수 있지만, 한쪽만으로 P0를 완료한 것으로 보지 않는다.

일반 변경은 사용자가 UI에서 대상과 작업을 명시적으로 미리 허용한 경우 별도 호출 승인 없이 실행한다. 삭제·대량·되돌리기 어려운 파괴 작업은 매 호출 별도 사용자 승인을 요구한다.

- Windows UI에서 여러 named target을 생성·수정·비활성화·삭제하고, 사용자가 각 대상의 인증 및 허용 범위를 관리한다.
- 사용자가 이름 붙인 서비스 묶음과 임의 이름의 환경을 만들고, 저장소 하나 이상과 등록된 Jenkins 작업, Harbor 이미지, Dashboard 네임스페이스·Deployment를 연결한다. 서비스 묶음은 연결 대상의 권한을 확대하지 않는다.
- GitHub Enterprise, Jenkins, Harbor, Kubernetes Dashboard의 REST/API 기능을 각각 연결한다. GitHub REST는 사용자가 UI에 직접 등록한 최소권한 Bearer PAT만 v0.x 인증 경로로 구현한다. 사용자가 필요한 읽기 권한만 부여한 토큰을 준비해야 하며, 앱은 upstream token scope/permission을 검사하지 않는다. `gh auth token --hostname HOSTNAME`은 안전한 일회성 가져오기와 stdout·오류·로그의 비밀 경계 및 host 일치를 검증하기 전까지 미구현 확장으로 둔다. `gh auth setup-git`와 SSH는 Git 전송이며 REST 인증 대안이 아니다. 실제 Enterprise 연결은 별도 확인 전까지 미검증이다.
- Kubernetes Dashboard 어댑터의 설계 기준은 공식 Helm chart release `7.14.0`이다. 이는 앱 버전이 아니다. 공식 tag의 `Chart.yaml`에는 `appVersion`이 없고 auth `1.4.0`, API `1.14.0`, web `1.7.0`, metrics-scraper `1.2.2` 조합을 지정한다. 배포·서비스·gateway 설정과 component 소스를 조사한다. 실제 회사 설치 버전, base URL, 프록시 경로, 인증 흐름 및 API 권한은 미검증이다. Dashboard 웹 REST 외에 직접 Kubernetes API 연결을 기본 경로로 두지 않는다.
- 비밀값을 UI에서 생성·교체·삭제하고 연결 대상에 참조시킨다. Windows에서는 Windows Credential Manager 사용을 우선한다. 값은 다시 화면이나 MCP 응답에 표시하지 않고, 일반 설정에는 비밀값 대신 참조만 둔다. 전역 환경변수 또는 `.env` 파일을 요구하지 않는다.
- MCP 도구로 대상별 조회를 제공하며, 사용자가 미리 허용한 범위 안에서 변경 작업도 수행한다. 대상 간 권한이 섞이지 않도록 한다. 임의 셸 실행이나 임의 주소 접근을 허용하지 않는다.
- 조회 결과·오류·로그를 MCP 응답으로 보내기 전에 민감정보를 가리고 크기·행 수·시간을 제한한다. 자격 증명 원문, Kubernetes Secret 데이터 등 불필요한 비밀 데이터는 기본 조회 대상에서 제외한다.
- Windows 현재 사용자 환경변수를 UI에서 등록·교체·삭제한다. 다른 변수와 기계 전체 설정을 바꾸지 않으며, 같은 계정의 프로세스가 값을 읽을 수 있다는 범위를 안내한다. Python/Docker 전용 실행·주입 기능은 P0 완성 조건에서 제외한다.
- 로그인 시 시작하는 상주 loopback HTTP MCP와 stdio MCP 경로를 제공한다. 이미 설치된 Codex·Claude·Gemini CLI에 기존 설정 백업 후 MCP를 자동 등록하고 각 클라이언트의 연결·도구 호출을 확인한다. CLI 프로그램 자체 설치는 범위에 넣지 않으며, 지원 버전과 검증 범위는 확인한 것만 표시한다.
- 한 번의 설치 흐름에서 필요한 값을 친절하게 입력하고 검증할 수 있다. 필수 인증이 없거나 연결이 실패하면 다음 조치를 분명히 안내한다.
- 기존 환경 가져오기는 사용자가 선택한 프로젝트의 Git remote, 지정한 문서·Runbook, SSH config 별칭, 기존 연결 설정에서 후보를 찾는다. 사용자가 지정한 대화/내보내기 자료만 입력으로 삼으며 `.env`·인증 파일의 비밀 원문을 AI 응답이나 로그로 보내지 않는다.
- 후보 미리보기에는 출처, 확신도, 미확인 항목, 권한 요약을 표시한다. AI가 연결·등록 작업의 초안을 만들거나 수정할 수 있지만, 새 비밀값 연결과 실행 권한 증가는 UI 미리보기와 사용자 승인 뒤에만 저장한다.
- 비밀값 없는 MCP 카탈로그 조회와 연결 상태 확인을 제공한다. 카탈로그는 등록된 연결 대상, 서비스 묶음·환경, 허용된 작업 이름을 보여주고 비밀 원문·자격 증명 참조 값을 반환하지 않는다.
- 대상, 서비스 매핑, 고정 작업은 설정으로 추가할 수 있다. 새 프로토콜/어댑터 또는 보안 정책 변경이 필요할 때만 코드 변경과 새 릴리스가 필요하다. 임의 URL·셸·SSH host·자격 증명을 받는 범용 실행기는 제공하지 않는다.

### P1 — 선택 확장

- PostgreSQL·SeaweedFS 전용 연결 작업 또는 Runbook. 자주 쓰는 SSH 연결·등록 작업 자체는 FR-7의 P0다.
- Windows 외 Ubuntu에서의 동등한 설치·비밀 저장 경험. Linux 비밀 저장소는 구현 전에 선택해야 한다.
- Codex·Claude·Gemini CLI 외 추가 클라이언트의 등록 자동화와 상태 점검.

P1은 P0의 안전한 연결·권한·출력 흐름을 약화시키지 않는 범위에서 추가한다. SCP 문서와 SCP MCP는 별도 제품/저장소 범위다.

## 5. 기능 요구사항과 수용 기준

### FR-1. 연결 대상 관리 (P0)

사용자는 고정된 환경 구분 없이 여러 대상에 이름을 붙이고, 대상별 endpoint, 인증 참조, 범위, 허용 작업을 관리할 수 있어야 한다.

**수용 기준**

- 같은 종류의 대상을 두 개 이상 등록해도 서로 다른 주소·비밀값·범위로 구분된다.
- MCP 호출은 명시된 대상에만 전달되며 다른 대상의 인증 정보나 허용 범위를 상속하지 않는다.
- 삭제·비활성화한 대상은 새 MCP 요청에서 사용할 수 없다.
- Harbor/Dashboard 서버 검증이 실패하면 사용자가 수정할 수 있도록 제출된 비밀 제외 입력값을 오류 화면에 남기되, 토큰·암호는 다시 표시하지 않고 검증 단계에서 설정·비밀 저장소·서비스 요청을 일으키지 않는다.

HTTP 422 재렌더에서는 오류 입력 하나에 `autofocus`를 부여하고 `aria-invalid` 및 연결된 오류 설명을 함께 표시한다. 렌더된 Harbor/Dashboard 검증 응답 테스트는 정확히 한 오류 입력만 자동 포커스되는 것을 검사한다. 실제 Chrome POST 후의 포커스는 별도 브라우저 검증 전까지 미확인이다.

### FR-2. 비밀값 관리 (P0)

사용자는 UI에서 이름 붙은 서비스·SSH 인증용 비밀값을 만들고, 교체하고, 삭제하며 연결 대상에 연결할 수 있어야 한다. 기존 Python 작업의 비밀 매핑은 보존되는 선택 기능이며 이 요구의 필수 범위가 아니다.

**수용 기준**

- 비밀값 입력 후 UI, 일반 설정 파일, MCP 목록·응답·오류 화면에서 원문을 다시 읽을 수 없다.
- Windows에서는 Windows Credential Manager에 비밀 원문을 저장하고 설정 파일에는 비밀 참조만 저장한다.
- 이름 있는 항목을 연결 설정에서 선택·재사용할 수 있다. 교체 시 사용 중인 연결 관계를 유지하며, 사용 중 항목 삭제는 영향 범위를 표시하고 미해결 참조를 만들지 않는다. 이름·저장 상태를 관리하는 UI와 값 원문을 다시 보여주는 UI를 구분한다.
- 교체는 연결 대상 ID와 서비스 묶음 매핑을 유지하고 새 값으로 적용된다. 저장용 비밀 참조는 새 값에 맞춰 새로 발급한다. 기존 참조 삭제 실패는 사용자에게 알려지고, 등록 대상은 새 참조를 사용한다.
- 서비스 인증 설정은 사용자 환경변수나 `.env`를 만들지 않고 완료할 수 있다. FR-6의 사용자 환경변수 관리는 별도 기능이며, Credential Manager 비밀을 환경변수로 자동 복사하지 않는다.

### FR-3. 연결 테스트·클라이언트 등록·앱 시작 (P0)

설정 UI는 입력 오류와 인증 실패를 구분해 보여주고, 사용자가 다음 조치를 알 수 있게 해야 한다.

**수용 기준**

- 정상·잘못된 주소·잘못된 자격 증명·접근 거부를 구분하는 테스트 결과를 표시한다.
- 오류 메시지에 비밀값, 전체 인증 헤더, 응답 내 민감정보가 포함되지 않는다.
- MCP 클라이언트 연결을 설정하거나 안내한 뒤 실제 초기 연결 상태를 확인할 수 있다.
- 앱이 관측하지 않은 단계는 사용자 보고 표시로만 표현하고 앱이 확인한 연결 상태와 구분한다.
- 자동 설정을 지원하지 않는 클라이언트는 지원한다고 표시하지 않고, 해당 클라이언트의 검증된 수동 설정 절차를 안내한다.
- 이미 설치된 Codex·Claude·Gemini CLI를 대상으로 MCP 등록을 자동화한다. 기존 설정을 백업하고 변경 범위를 보여주며 다른 서버·사용자 설정을 보존한다. 반복 등록은 중복 항목을 만들지 않고 백업에서 이전 설정을 복원하는 절차를 제공한다. 자동 rollback은 필수 구현으로 두지 않는다.
- 저장된 등록 정보, 실제 MCP 초기 연결, 도구 호출 성공을 별개로 확인한다. 외부 서비스 연결 성공과 MCP 클라이언트 연결 성공도 구분한다. 각 CLI·버전·전송별 미검증 항목을 표시한다.
- Windows 현재 사용자 로그인 시 앱을 자동 시작할 수 있고 UI에서 해제할 수 있다. 상주 HTTP의 단일 소유 프로세스와 중복 실행, 포트 충돌, 종료·재시작을 처리한다. 도구 호출마다 서비스 어댑터를 가진 앱을 새로 실행할 필요가 없어야 한다.

### FR-4. 서비스별 MCP 작업 (P0)

GitHub, Jenkins, Harbor, Kubernetes Dashboard REST 대상에 대해 대상별로 허용된 조회 및 변경 기능을 제공한다. UI와 도구 이름은 사용자가 서비스와 대상을 알아보기 쉽게 표현한다.

**수용 기준**

- 대상마다 허용한 저장소·job·프로젝트·네임스페이스 등 범위를 검사한다.
- 읽기와 변경 작업의 권한을 구분한다. 사전에 허용되지 않은 작업은 서비스에 요청하기 전에 거부한다.
- Jenkins MCP는 등록된 대상 이름과 고정 job path만 사용하며 URL, path, parameter를 인자로 받지 않는다. Trigger는 기본 거부한다. 대상 UI의 명시적 체크는 해당 등록 job이 비운영이라는 사용자의 attestation이며, 체크한 job은 매 호출 UI 확인 없이 trigger를 허용한다. 이 attestation이 없으면 호출마다 loopback 브라우저에서 1회 확인을 받아야 한다. 확인 화면에는 등록 대상 이름, proxy/context path를 포함한 정확한 Jenkins base URL, environment label, 고정 job path를 표시한다. label만으로 비운영 여부나 허용을 추론하지 않는다. 거부·취소·시간 초과·listener 또는 브라우저 실행 실패, 확인 뒤 대상 설정 변경은 POST 전에 fail closed 한다.
- Trigger POST의 전송 실패·redirect·5xx 등으로 수락 여부가 모호하거나, 201 응답의 queue Location이 없거나 안전한 queue ID로 검증되지 않으면 `outcome_unknown`과 재시도 금지 안내를 반환하고 자동 재전송하지 않는다. 수락된 trigger의 숫자 queue ID와 queue 응답의 ID·task name/URL을 등록 job에 결합해 검사한다. 수락 후 조회 실패는 `inspection_pending`으로 반환하며 POST를 반복하지 않는다.
- Build number를 Jenkins 응답과 대조하고 로그는 32 KiB 이하 offset page로 제공한다. 후속 page는 read-only MCP 도구로 조회하며 알려진 credential과 일반 자격 증명 형식을 마스킹한다. 완전한 비밀 유출 방지는 보장하지 않는다.
- 설정한 작업 권한에 따라 허용된 변경을 에이전트가 호출할 수 있다. 삭제·대량·되돌리기 어려운 파괴 작업은 매 호출 별도 사용자 승인을 요구하며, 임의 명령은 허용하지 않는다.
- GitHub Enterprise API origin은 저장된 주소에 고정하고, 다른 origin으로의 리다이렉트에는 인증값을 보내지 않는다. v0.x REST 인증은 UI에서 직접 등록한 최소권한 Bearer PAT만 지원한다. 앱은 upstream 권한을 검사하지 않으므로 사용자가 필요한 읽기 권한만 부여한 토큰을 선택해야 한다. `gh auth token --hostname HOSTNAME`은 안전한 일회성 가져오기·stdout 비밀 경계·host 일치를 검증하기 전까지 미구현 확장이다. `gh auth setup-git`와 SSH는 Git 전송에만 사용한다. 실제 Enterprise 연결은 미검증이다.
- Kubernetes Dashboard는 공식 `kubernetes-dashboard-7.14.0` Helm chart release를 설계 기준으로 삼는다. chart version과 앱 버전을 혼동하지 않으며, 해당 tag가 지정한 auth 1.4.0, API 1.14.0, web 1.7.0, metrics-scraper 1.2.2 조합을 추적한다. 실제 회사 설치 chart/component 버전, base URL/subpath 및 proxy rewrite, SSO·인증 동작과 권한은 검증 전이다. 브라우저에서 사용하는 Dashboard 웹 REST를 대상으로 하고 직접 Kubernetes API를 대체 어댑터로 삼지 않는다.

### FR-5. 출력 제한과 비밀값 마스킹 (P0)

MCP 서버는 외부 서비스 응답이 AI 문맥에 들어가기 전에 결과를 제한·정리해야 한다.

**수용 기준**

- 등록된 비밀값을 포함하는 테스트 응답은 도구 응답·오류·로그 어디에도 원문을 포함하지 않는다.
- 토큰, 비밀번호, 인증 헤더, Kubernetes Secret 데이터 등 알려진 민감 필드를 서비스별 규칙으로 제거하거나 마스킹한다.
- 로그·목록은 설정된 최대 크기와 개수만 반환하고, 초과 시 잘렸음을 표시한다.
- 마스킹 처리 실패 시 원문을 반환하지 않는다.
- 이 기능을 비밀 유출의 완전한 방지로 표현하지 않는다. 형식이 알려지지 않은 애플리케이션 비밀 문자열이 로그 등에 기록될 수 있다.

### FR-6. Windows 사용자 환경변수 관리 (P0)

사용자는 UI에서 현재 Windows 사용자 범위의 이름 있는 환경변수를 등록·교체·삭제하여 계정의 프로그램에서 사용할 수 있어야 한다. 로컬 Python/Docker 명령은 기존 AI 도구로 실행하며 하네스의 전용 실행기로 묶지 않는다.

**수용 기준**

- 현재 사용자 환경변수의 이름과 관리 상태를 확인하고, 개별 값을 추가·교체·삭제할 수 있다. 이름 충돌과 잘못된 입력을 저장 전에 표시하며 선택하지 않은 변수를 보존한다.
- 기계 전체 환경변수와 `.env` 파일은 쓰지 않는다. 서비스 인증용 Credential Manager 항목을 환경변수로 자동 복사하지 않는다.
- 저장된 값 원문은 UI 재열기, MCP 응답, 오류·로그에 다시 넣지 않는다. 값의 입력은 로컬 UI에서 하고 AI 초안에는 비밀 원문을 넣지 않는다.
- 같은 계정의 프로세스가 값을 읽을 수 있음을 안내한다. 사용자 환경변수를 Credential Manager와 같은 보관 경계나 작업별 격리로 설명하지 않는다.
- 변경 결과와 실패 시 다음 조치를 표시한다. 이미 실행 중인 AI·터미널의 환경이 즉시 갱신됐다고 가정하지 않으며 새 프로세스·세션에서 적용 여부를 확인하는 절차를 제공한다.
- 기존 Python 실행 코드는 보존하되 이 FR의 수용·완료 근거로 사용하지 않는다. 로컬 Docker 실행기와 Python 전용 비밀 주입은 첫 제품의 필수 구현으로 잡지 않는다.

`registered_python_tasks`는 설정에 저장된 유효한 지문이 있는 활성 작업 이름만 반환하며 executable/script 파일을 열거나 `Stat`하지 않는다. 따라서 목록 조회는 삭제되었거나 네트워크 경로가 된 파일을 탐지하지 않는다. 실행은 이름으로 등록된 작업을 찾은 뒤 승인 전에 지문을 확인하고, 승인 후 설정 revision과 지문을 다시 대조한다. 선택된 비밀 참조를 읽은 뒤에도 프로세스 시작 직전에 지문을 확인한다. SHA-256 검사는 변경 파일을 fail-closed로 차단하지만 마지막 검사 후 파일이 바뀌는 TOCTOU 경합은 남는다. Windows 경로는 rooted drive-letter 형식만 허용해 UNC 및 DOS/NT device namespace 경로를 거부한다. drive letter로 매핑된 네트워크 경로인지 여부는 판별하지 못한다. 승인 경계 테스트는 합성 loopback HTTP client를 사용하며 실제 desktop browser 승인과 Python runtime 호환은 미검증이다.

승인 뒤 최신 task 설정 대조, 지문 확인, 선택된 secret reference 조회, 마지막 지문 확인과 child process `Start()`는 같은 config lock 안에서 직렬화된다. 이는 그 구간에 설정·secret mapping 변경이 끼어들지 못하게 하며, child가 시작된 직후 lock을 해제해 실행 대기 중에는 설정 편집을 막지 않는다. 승인 완료 페이지를 신호하기 전에 응답을 flush한다. SHA-256 지문은 파일 변경 탐지 경계를 추가하지만, OS가 파일을 열기 전에 발생할 교체 경합이나 프로세스 격리를 제공하지 않는다.

### FR-7. SSH 연결·등록 작업 (P0) 및 데이터베이스 확장 (P1)

사용자는 이름 붙은 SSH 서버와 허용 작업을 등록하고 AI가 이를 재사용하게 할 수 있어야 한다. 원격 Docker 명령도 필요한 경우 SSH의 등록 작업으로 다룬다. 로컬 Docker daemon이나 별도 원격 컨테이너 관리기를 만들 것을 전제하지 않는다. PostgreSQL·SeaweedFS 전용 기능은 후속 P1이다.

**수용 기준**

- 대상 서버·데이터베이스 주소와 허용 작업은 사용자가 등록한 값으로 고정된다.
- SSH를 통한 임의 서버·임의 명령 실행은 기본 허용하지 않는다.
- 조회와 변경, 파괴적 작업은 구분되어 허용 범위를 검사한다.
- SSH 인증과 호스트 신뢰 확인은 사용자가 선택한 연결 설정에 결합한다. 모델이 host·키·자격 증명·임의 셸 문자열을 요청 인자로 바꾸지 못하게 한다.
- 출력은 FR-5에 따라 제한·마스킹하고 실패 본문을 원문으로 돌려주지 않는다. 시간 초과·취소 시 로컬 SSH 종료와 원격 명령 종료 확인을 구분한다. 원격 종료를 확인하지 못했으면 그 상태를 표시하고 변경 작업을 자동 재전송하지 않는다.
- 사전 허용된 정확한 일반 비운영 작업은 반복 확인 없이 실행한다. AI가 새 작업 초안을 만들거나 범위를 넓히면 UI 검토·승인을 거치며 운영 변경·파괴 작업은 매 호출 확인한다.

### FR-8. 서비스 묶음 및 환경 매핑 (P0)

사용자는 여러 저장소(최소 1개), 임의 이름의 선택적 환경, 연결 대상 및 리소스를 서비스 묶음 하나에 연결할 수 있어야 한다. 환경 이름은 라벨이며 고정 `dev`/`prod` 의미를 갖지 않는다.

**수용 기준**

- 묶음은 등록된 GitHub 저장소, Jenkins job, Harbor image/project, Dashboard namespace·Deployment에 대한 명시적 참조만 저장한다.
- 묶음과 환경의 추가·수정은 UI 설정으로 가능하며 대상의 리소스·작업 정책보다 넓은 호출을 허용하지 않는다.
- AI가 묶음 이름으로 관련 등록 대상과 허용 작업을 찾을 수 있고, 없는 매핑은 임의 endpoint 탐색으로 대체되지 않는다.

### FR-9. 기존 환경 가져오기와 등록 초안 (P0)

전체 요구사항은 사용자가 선택한 프로젝트의 Git remote, 명시적으로 선택한 문서·Runbook, SSH config 별칭, 기존 연결 설정 및 사용자가 지정한 대화·내보내기 자료에서 후보 등록안을 미리 보는 것이다. 다른 AI 클라이언트의 과거 대화 전체를 자동으로 읽는다고 가정하지 않는다.

**핵심 수용 기준:** 초기 설정은 AI와 대화하며 만든다. AI가 현재 사용자가 지정한 대화 맥락과 선택 문서에서 비밀값 없는 연결·서비스 묶음·SSH 작업 초안을 제출하고, 앱은 출처·미확인 값·권한·기존 설정과의 차이를 보여준다. 승인한 부분만 저장하며 새 비밀값 입력·매핑과 실행 권한 증가는 로컬 UI에서 검토·승인한다. 비밀 원문과 Credential Manager 참조는 MCP 입력으로 받거나 반환하지 않는다. 앱이 다른 클라이언트의 대화를 직접 읽거나 내부 모델 호출을 구현할 것을 요구하지 않는다. ChatGPT export 파일 파싱과 대화 개수 집계는 첫 제품의 필수 조건에서 제외한다. 아래 파일 preview 구현은 이 AI 초안→승인→저장 흐름의 완료 근거가 아니다.

Git 설정 파서는 지원 remote URL만 처리하고 include를 읽거나 Git·셸·SSH를 실행하지 않는다. Runbook 파서는 UTF-8 `.md`/`.txt`에서 `lah:repository <Git remote URL>` 형식과 정확히 일치하는 줄만 처리한다. 최대 512줄과 32개 고유 참조를 허용하고 동일 참조는 횟수로 합친다. 일반 문서 내용은 해석하거나 결과로 돌려주지 않는다. 두 입력의 후보는 출처·확신도·미확인 Jenkins·Harbor·Dashboard 매핑과 권한을 표시하며, 활성 GitHub 대상의 origin과 repository가 정확히 일치해야 선택 후보가 된다. 후보당 최대 8개 매치를 표시하고 추가 매치가 있으면 알린다. 별도 SSH config preview는 사용자가 고른 이름 `config` 파일에서 최대 512줄·32개 alias까지 제한된 리터럴 `Host` alias 목록만 반환한다. 실제 경로는 확인하지 않으며 `HostName`·사용자·키·proxy 값은 표시하지 않는다. `Include`·`Match`, wildcard·negation, 중복 alias, 전역·중복·비literal `HostName`, 잘못된 `Host`/`HostName` 형식과 줄 이어쓰기는 거부한다. 그 밖의 지시자는 opaque text로 취급하고 파싱·반환·실행하지 않는다. alias는 repository나 등록 GitHub 대상과 연결되지 않으며 SSH 접속·인증·명령 실행을 뜻하지 않는다. 설정 JSON preview는 Local Agent Harness가 만든 v4/v5/v6/v7 JSON만 strict decode·schema validation한 뒤 버전, adapter별 대상 수, 비활성 대상 수, 서비스 묶음·환경 수를 표시한다. v5~v7은 Python 작업 수와 비활성 작업 수를 포함한다. v6/v7의 환경 변수명·secret reference와 v7 fingerprint는 allowlist·값 검증에만 쓰이며 응답에는 Python 작업 수 외의 세부를 복사하지 않는다. ID·이름·실행 경로·URL·사용자명·credential reference·file digest·승인 세부·연결 이력·원문은 응답에 넣지 않는다. 중복 JSON 키, 대소문자 변형 키, null, 알 수 없는 필드, 구버전·후행 데이터는 거부한다. Git/Runbook/JSON remote 후보 preview는 파싱을 통과한 입력에 한해 활성 설정을 읽어 기존 활성 GitHub 대상과의 일치 여부만 계산한다. 설정을 쓰거나 Credential Manager를 읽고 쓰거나 외부 네트워크를 사용하지 않는다. Git/Runbook 후보를 고른 경우에만 사용자가 서비스 묶음 폼에서 저장해야 매핑이 반영된다. 대화·내보내기의 conversation schema/count parser는 아직 미구현이다.

Git preview는 remote alias, repository, 매치된 기존 대상 이름을 응답하기 전에 기존 `cleanOutput`의 알려진 토큰·credential 패턴 필터에 통과시킨다. exact origin/repository 매칭은 필터 전 값으로 수행한다. 이 필터는 알려진 패턴을 줄이는 방어이며 모든 비밀정보를 탐지·제거한다고 보장하지 않는다.

별도 `/preview-json-remotes` endpoint는 사용자가 고른 `.json`에서 키가 아닌 각 JSON 문자열 값 전체만 검사한다. URL 부분 문자열을 찾아내거나 문자열 앞뒤 공백을 제거하지 않는다. 4 KiB보다 긴 문자열 값은 건너뛰고 중첩 깊이 64, JSON decoder token 32,768개, 중복 제거한 후보 32개를 제한한다. 중복 key, 잘못된 UTF-8/JSON, 후행 값, 깊이·token·candidate 상한 초과는 일부 후보를 내보내지 않고 전체 거부한다. 기존 안전 remote parser에서 HTTPS Git remote로 확인된 후보만 canonical origin/repository로 중복 제거한다. 모든 결과는 고정된 낮은 신뢰도와 `cleanOutput` 처리된 저장소 문자열만 포함하고 URL·host·source value·key·filename·target ID/name은 포함하지 않는다. 정규화한 origin/repository가 활성 GitHub target과 일치하는 경우에만 boolean manual-review signal을 표시한다. 알려진 토큰 패턴 정리는 모든 비밀정보 제거를 보장하지 않는다. 이 기능은 대화 schema나 count parser가 아니며 대상을 선택하거나 저장하지 않는다.

**기존 파일 미리보기 slice의 검증 기준**

- Git 입력은 이름이 `config`인 파일 하나, Runbook 입력은 확장자를 대소문자 구분 없이 확인하는 `.md` 또는 `.txt` 파일 하나와 CSRF 필드 하나로 제한한다. 둘 다 64 KiB 파일·72 KiB multipart 요청·64 KiB JSON 응답 상한을 적용하고 추가 필드·파일은 거부한다.
- 기존 연결 설정 preview는 사용자가 고른 `.json` 파일 하나와 CSRF 필드 하나만 받는다. 1 MiB 파일·1 MiB+8 KiB multipart 요청·8 KiB JSON 응답 상한을 적용하고 추가 필드·파일과 중복 `Content-Disposition` 헤더를 거부한다. Local Agent Harness의 v4/v5/v6/v7 스키마만 지원하며 versioned migration을 실행하지 않는다. v5~v7은 Python 작업 수와 비활성 작업 수를 추가한다. v6/v7 secret mapping과 v7 fingerprint 필드는 allowlist·값 검증만 하며 별도 mapping/digest 세부를 반환하지 않는다. 이름·경로·참조는 반환하지 않으며 Credential Manager를 읽지 않는다. 엄격한 canonical key 검사 전 중복 키를 거부하고 알 수 없는 필드, case-variant 키, `null`, 후행 값 및 잘못된 스키마를 거부한다.
- schema-neutral JSON repository preview는 `.json` 하나만 받고 파일 1 MiB·multipart 1 MiB+8 KiB·응답 64 KiB, depth 64·decoder token 32,768개·고유 후보 32개 상한을 적용한다. 키와 문자열 값 4 KiB 초과를 건너뛰고 각 짧은 문자열 값 전체만 제한된 remote parser에 전달한다. 중복 key·잘못된 UTF-8/JSON·trailing value·상한 초과는 전체 응답을 고정 오류로 끝내고 부분 후보를 내보내지 않는다. 후보는 canonical origin/repository로 dedupe하고 낮은 신뢰도 및 활성 대상 일치 boolean만 보인다. 원문·URL·host·JSON key·filename·target ID/name은 결과에 넣지 않는다. 대화 schema/count를 뜻하지 않는다.
- Git remote URL과 Runbook의 명시적 repository 지시자를 제한 파서로 검증한다. 지원하지 않는 스킴·경로, userinfo, query, fragment, escape 및 잘못된 지시자를 거부한다. Runbook은 UTF-8·512줄·32개 고유 참조까지 허용하고 중복을 합친다. 어떤 파서도 include·명령·네트워크를 실행하지 않으며 오류는 업로드 원문을 되돌려주지 않는다.
- Git preview는 출력 alias·repository·대상 이름에 알려진 패턴 필터를 적용하고, canary 테스트에서 필드 가림과 exact match 유지 및 설정·secret store·외부 네트워크 무부작용을 확인한다. 이 패턴 필터를 완전한 비밀 탐지로 표현하지 않는다.
- 후보는 입력 출처·repository·확신도와 미확인 Jenkins/Harbor/Dashboard/권한을 보여준다. 일치 기준은 활성 GitHub 대상의 정확한 origin과 repository다. 후보당 최대 8개를 표시하고 추가 매치 안내와 낮은 확신도를 확인한다. 다른 대상을 자동 연결하지 않고 미일치 후보로 새 대상이나 권한을 만들지 않는다.
- SSH 입력은 별도 UI 모드에서 사용자가 직접 고른 정확한 파일명 `config`만 처리한다. 제한된 리터럴 `Host` alias만 표시하고 alias 외 설정 값은 반환하지 않는다. `Include`·`Match`, wildcard·negation·중복 alias, 전역·중복·비literal `HostName`, 잘못된 `Host`/`HostName` 형식과 줄 이어쓰기는 거부한다. 그 밖의 지시자는 opaque text로 취급하고 파싱·반환·실행하지 않는다. repository·host·GitHub API origin·target 간 대응을 추측하지 않으며 선택·저장·연결 동작을 제공하지 않는다.
- 미리보기 요청은 설정을 바꾸지 않고 Credential Manager를 읽거나 쓰지 않는다. 다만 Git/Runbook/JSON remote candidate preview는 exact match만 계산하기 위해 활성 설정을 읽는다. 원문 문서와 remote URL은 응답·오류·로그에 포함하지 않는다. 설정 JSON count preview는 버전·종류별 개수만 반환하며 ID·이름·주소·사용자명·secret reference·승인 정보·연결 이력을 제외한다. schema-neutral JSON remote preview는 저장소 문자열과 fixed-source label, 낮은 신뢰도, target match boolean만 반환한다. 대상 선택은 Git/Runbook의 기존 서비스 묶음 폼에 반영되며 사용자가 해당 폼을 저장해야 설정에 기록된다.
- 사용자가 지정하지 않은 대화 자료는 읽지 않는다. `.env`와 인증 파일은 입력원으로 자동 탐색하지 않으며 비밀 원문은 AI 응답·오류·로그로 보내지 않는다.

### FR-10. 카탈로그와 연결 진단 (P0)

AI는 등록 대상·서비스 묶음·환경·허용 작업을 비밀값 없이 조회하고, 사용자가 등록한 연결의 상태를 시험할 수 있어야 한다.

**수용 기준**

- 카탈로그에는 이름, 유형, 등록된 범위와 허용 작업의 요약을 반환하며 비밀 원문과 내부 비밀 참조를 반환하지 않는다.
- 연결 상태는 최근 테스트 시각과 성공·실패·미실시 상태를 구분한다. 상태 조회는 서버에 요청을 보내는지 여부를 사용자에게 알리고 결과를 민감정보 필터에 통과시킨다.
- 카탈로그나 진단 입력으로 임의 endpoint·자격 증명·권한을 지정할 수 없다.
- `registered_target_connection_test`는 어댑터와 정확한 등록 대상 이름만 받는다. 활성·유효 대상과 credential을 확인한 다음 그 대상의 기존 read-only GET 경로로 한 번 요청하고 로컬 이력 저장을 시도한다. 요청 전 거부는 이력을 바꾸지 않으며 `completed_at`은 이력이 저장된 경우에만 포함한다. 외부 요청과 로컬 설정 쓰기가 발생할 수 있음을 도구 설명에 알린다.
- 연결 시험 결과에는 주소·내부 ID·credential reference·응답 본문/헤더·raw error가 없어야 한다. 고정된 결과/안전 안내만 반환하고 기존 12초 제한, secret 정리, 요청 중 변경·삭제된 대상 결과의 기록 거부를 유지한다.
- 로컬 UI는 사용자가 직접 선택하고 실행한 경우에만 저장된 서비스 묶음·환경의 Dashboard 상태·이벤트·Pod 읽기 진단을 한다. 임의 endpoint·namespace·Pod·credential 입력은 받지 않고, 최대 5회의 제한된 GET과 12초 제한을 고지한다. 설정과 연결 이력은 변경하지 않으며 로그는 별도 흐름으로 남긴다.
- 진단 결과에 표시된 Pod/container에 대해서만 별도 UI 로그 동작을 제공한다. 로그 요청은 저장된 서비스 묶음·환경과 현재 Pod/container inventory를 다시 확인하며, 12초·100줄·줄당 4 KiB·64 KiB 응답 상한을 적용한다. 진단의 5회 GET 예산에는 로그 요청이 포함되지 않는다고 UI에서 구분한다.
- UI 진단은 부분 성공·단계별 고정 오류 안내·응답 또는 항목 축소 사실을 표시하고, 읽기 성공만으로 Deployment가 정상이라고 단정하지 않는다. 결과의 고정 문구는 한·영으로 제공하고 외부 투영 값은 데이터로 렌더링한다.

MCP Dashboard 로그 도구는 `text content`와 `structuredContent`를 포함한 직렬화 `CallToolResult` 전체를 64 KiB 이하로 제한한다. UI `/dashboard-diagnosis-logs` handler는 별도 JSON response envelope를 64 KiB 이하로 제한한다. 이 둘은 같은 상한을 서로 다른 투영에 적용한다.

### FR-11. 설정 기반 확장 경계 (P0)

사용자는 코드 변경 없이 등록 대상, 서비스 매핑, 사전 정의 작업을 설정으로 추가할 수 있어야 한다. 새 프로토콜/어댑터 또는 공통 보안 정책 변경만 코드 릴리스 대상으로 둔다.

**수용 기준**

- 설정은 기존에 구현된 서비스 종류와 작업 유형 안에서 검증된다. 임의 URL 호출, 셸 명령, SSH host 또는 비밀값을 직접 받는 범용 MCP 도구를 제공하지 않는다.
- 허용되지 않거나 미지원인 설정은 저장 또는 실행 전에 거부되고, 사용자가 다음에 취할 행동을 알 수 있다.

## 6. 비기능 요구사항

### NFR-1. 로컬 보안 경계

- 기본 HTTP 리스너는 loopback에서만 접근 가능해야 한다. 원격 클라이언트에 로컬 서버를 공개하는 것은 범위 밖이며 등록된 외부 서비스·SSH로의 연결과 구분한다.
- 로컬 UI의 상태 변경 요청은 외부 웹페이지가 임의로 실행하지 못하도록 보호한다.
- MCP 응답과 앱 로그에는 비밀 원문이나 인증 헤더를 남기지 않는다.
- 서비스 인증 비밀은 Credential Manager에 보관하고 사용자 환경변수 관리와 노출 범위를 구분한다. 사용자 환경변수의 값은 같은 계정의 프로세스·AI 셸이 읽을 수 있다. MCP 마스킹은 하네스가 반환하는 응답에 적용되며 AI가 별도로 셸에서 환경값을 읽는 경로를 차단하지 않는다. Credential Manager도 같은 OS 계정의 임의 프로그램으로부터 완전한 격리를 제공하지 않는다.

### NFR-2. 사용성

- 첫 설치, 첫 비밀값 등록, 첫 대상 연결, 첫 MCP 호출까지 한 흐름에서 안내한다.
- 로컬 UI의 메뉴·입력·설명·상태·오류를 한국어와 영어로 제공하고 화면에서 언어를 바꿀 수 있게 한다. 새로고침과 폼 제출 뒤에도 선택을 유지하며 알 수 없는 언어값은 안전한 기본값으로 처리한다. MCP 도구명과 프로토콜 필드는 번역하지 않는다.
- 주소·인증·허용 범위가 어떤 대상에 적용되는지 항상 보인다.
- 오류는 원인과 사용자가 취할 다음 행동을 짧게 알려준다.
- 저장된 비밀값을 확인하기 위해 다른 도구나 시스템 환경변수 설정을 요구하지 않는다.

### NFR-3. 응답 안정성

- 외부 서비스 요청에는 시간·응답 크기 제한을 둔다.
- 외부 오류, timeout, 마스킹 실패를 안전하게 처리하고 원문 응답을 우회 반환하지 않는다.
- 한 대상의 실패가 다른 대상의 설정이나 작업을 바꾸지 않는다.
- 상주 앱의 중복 실행·포트 충돌·종료·재시작과 여러 MCP 클라이언트의 연결을 검증한다. 호출마다 앱이 재시작되지 않는지 실제 프로세스 수와 연결 흐름으로 확인한다. 백신 시작 지연의 수치 개선을 측정 없이 약속하지 않는다.
- 기능별 시간·응답·동시 실행 제한과 잘림·부분 실패·결과 미확인 상태를 문서화한다. 변경 요청의 결과가 모호하면 자동 재전송하지 않는다. 수치 목표는 실제 사용하는 흐름과 측정 근거로 정한다.

### NFR-4. 호환성

- Windows 11을 우선 지원하고 실제 설치 UI, MCP 클라이언트 연결, Credential Manager 접근을 Windows에서 검증한다.
- Ubuntu 지원은 제품 방향에 포함하되, 비밀 저장 및 클라이언트 연결 방식이 검증되기 전에는 기능 동등성을 약속하지 않는다.
- Codex, Claude, Gemini 및 데스크톱 클라이언트는 이름만으로 호환된다고 간주하지 않는다. 지원 버전과 설치 절차는 실제 연결 검증 결과로 관리한다.

## 7. 범위 밖

- SCP 매뉴얼 수집·검색 및 SCP MCP.
- 임의 셸, 임의 URL, 임의 SSH 서버를 AI가 직접 지정해 실행하는 범용 원격 실행기.
- 모든 비밀 패턴이 어떤 로그에서도 발견·마스킹된다는 보장.
- 팀 공유형 비밀 저장소, 중앙 서버, 조직 계정 관리.
- 사용자가 관리하지 않는 서비스의 자동 발견이나 권한 상승.
- 실행 시점에 임의 코드를 내려받아 추가하는 런타임 플러그인 시스템. 확장은 코드 변경과 검증을 통해 추가한다.
- 고정된 `dev`/`prod` 제품 모델.

## 9. 문서와 구현의 관계

이 PRD는 구현 단계의 요구사항 기준 초안이다. 모든 기능은 코드와 실제 실행 증거가 생기기 전까지 미구현·미검증이다. 예전 `devops-mcps` 저장소는 과거 프로토타입이며 새 제품의 코드, 고정 `dev`/`prod` 구조, Kubernetes API 직접 연결의 기본 근거가 아니다. SCP 문서와 MCP는 저장소 범위 밖이다.
