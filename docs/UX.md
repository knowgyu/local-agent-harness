# UX 설계

이 문서는 Windows에서 실행하는 로컬 앱의 목표 UX를 정한다. 사용자는 개발 시스템을 설정하고 AI 에이전트에 허용 범위를 정한다. 에이전트가 도구를 쓰기 위해 사용자가 매번 명령어·토큰·URL을 다시 찾아 설명하지 않아도 되어야 한다. 이전 프로토타입의 UI 구성은 새 제품의 템플릿으로 삼지 않는다.

## 사용자의 불편과 UX 목표

- 환경변수나 프로젝트별 `.env`를 직접 만들고 관리하기 번거롭다. 서비스 비밀값은 앱에서 이름을 붙여 Windows Credential Manager에 저장하고, 연결 설정에서 골라 쓴다.
- Jenkins, Harbor, GitHub, Kubernetes 접속 정보와 위치를 매번 AI에게 전달하고 싶지 않다. 사용자가 이름을 붙인 여러 대상을 등록하고 각 대상의 주소·계정·범위를 고정한다.
- 로그·Pod 응답을 읽다가 토큰이나 Secret이 프롬프트에 들어갈까 걱정된다. 민감값을 도구 출력 전에 제거하고, 연결 정보·토큰·원문 오류 응답을 에이전트에게 돌려주지 않는다.
- 기존 MCP 설정은 클라이언트마다 다르고 상태를 알기 어렵다. Codex·Claude·Gemini의 등록 상태와 재시작 필요 여부를 실제 확인 결과로 보여준다.
- AI가 할 수 있는 일을 사용자가 미리 정해 휴먼 에러와 반복 확인을 줄이고 싶다. 대상·리소스·작업별로 허용 범위를 설정하고 그 안에서는 매번 묻지 않고 실행한다.

성공 기준은 처음 실행부터 한 대상을 등록하고 연결 테스트를 통과시킨 뒤, AI 클라이언트가 그 대상을 제한된 권한으로 쓰기까지 사용자가 안내를 찾아다니지 않는 것이다.

## 정보 구조

exe 실행 시 로컬 웹 UI를 기본 브라우저에서 연다. 자동으로 열리지 않으면 loopback 주소와 복사 버튼을 보여준다. UI는 loopback에서만 접근한다.

```text
Local Agent Harness                         로컬 서비스 상태
대상   서비스 묶음   비밀값   AI 도구   연결 진단   설정

연결 대상
[+ 연결 추가]
이름             서비스     범위 요약              연결 상태       작업
개발 CI           Jenkins    team-a/build           연결 확인됨     편집 · 테스트
이미지 저장소     Harbor     project-x              확인 필요       편집 · 테스트
```

### 화면

- **연결 대상**: 등록한 Jenkins·Harbor·GitHub·Kubernetes Dashboard 등을 이름, 서비스 종류, 범위 요약, 마지막 테스트 상태로 표시한다. 핵심 화면이며 사용 빈도가 높은 작업을 바로 시작한다.
- **비밀값**에는 이름과 사용처만 표시하고 원문은 다시 보여주지 않는다.
- **AI 도구**에는 MCP와 실제 검증한 클라이언트 등록 상태를 표시한다.
- **연결 진단**에는 대상별 최근 테스트 결과와 다음 조치를 보여준다. **설정**에는 로컬 앱 설정을 둔다. 장식용 통계 대시보드는 만들지 않는다.

대상 추가/편집은 별도 마법사 여러 단계로 쪼개지 않는다. 한 화면의 기본 항목은 바로 보이고, 세부 권한은 접을 수 있는 “허용 작업” 영역에서 설정한다. 현재 위치와 저장 상태는 항상 보인다.

## 연결 대상 계약

모든 서비스 대상은 사용자가 정한 이름으로 식별한다. `dev`/`prod` 같은 고정 이름이나 개수 제한을 강제하지 않는다. 이름은 중복을 막고 유형을 함께 보여 혼동을 방지한다.

| 서비스 | 기본 인증 입력 | 사용자가 정하는 범위 |
|---|---|---|
| Jenkins | 서버 주소, 사용자명, API Token | 허용된 job 경로와 작업 |
| Harbor | 서버 주소, 사용자 ID, 비밀번호 | 프로젝트/저장소와 작업 |
| GitHub Enterprise API | 정확한 Enterprise 주소와 PAT | 허용 조직·저장소와 작업. 요청 origin은 저장 주소에 고정 |
| GitHub SSH | 저장소 주소, Windows의 OpenSSH 인증 | 허용 저장소의 Git 전송 작업만. REST API 인증을 대체하지 않음 |
| Kubernetes Dashboard | 사용자가 입력한 기본 주소, 실제 설치에서 확인한 인증 | 확인된 웹 REST 경로와 허용 namespace·resource·작업 |

인증값 입력에는 기존 비밀값을 선택하거나 `+ 새 비밀값`으로 저장하는 동작을 둔다. 비밀값은 앱을 통해 Windows Credential Manager에만 저장하며 서비스용 환경변수·`.env`를 만들지 않는다. 저장 후 입력란은 지우고 이름과 “저장됨”만 보여준다.

연결 범위는 주소와 별개로 요약해 보여준다. 기본 권한은 읽기다. 쓰기·배포·삭제·Pod exec 같은 작업은 각각 명시적으로 허용하게 한다. 사용자가 허용한 대상·범위·작업 안에서는 AI가 매번 확인을 요구하지 않는다. 허용되지 않은 대상이나 범위 밖 요청은 실행 전에 거부 이유와 수정 위치를 알려준다. 임의 URL·셸 명령을 입력해 실행하는 기능은 일반 연결 설정에 섞지 않는다.

## 주요 흐름

### 첫 실행과 첫 연결

1. 사용자가 exe를 실행한다. 기본 브라우저에 로컬 UI가 열리고 “연결 대상을 추가하세요”라는 빈 상태를 보여준다. 브라우저가 자동으로 열리지 않으면 앱에 표시된 주소로 접속한다.
2. `연결 추가`를 눌러 서비스를 고르고, `이름`을 자유롭게 정한다. dev/prod 선택을 강제하지 않는다.
3. 주소·계정·인증 방식을 입력한다. 기존 비밀값 선택 또는 이름을 정해 새 비밀값을 저장한다. GitHub SSH 방식이면 기존 OpenSSH 인증을 테스트하고 개인 키 내용을 앱에 붙여넣게 하지 않는다.
4. 범위를 선택하고, 기본 읽기 권한과 추가 허용 작업을 검토한다. 저장 전 한 줄 요약을 보여준다. 예: “`개발 CI`가 `https://…`의 `team-a/build` job 상태와 로그만 조회”.
5. `연결 테스트`를 누르면 단계별 결과를 보여준다. 실패해도 입력한 대상과 값은 잃지 않으며, `저장` 또는 수정으로 이어갈 수 있다. 테스트하지 않은 연결을 “연결됨”으로 표시하지 않는다.
6. AI 도구 화면에서 사용할 클라이언트를 등록하고 상태를 확인한다. 클라이언트가 재시작되어야 하면 어떤 앱을 재시작할지 이름을 알려준다.

### 대상 편집과 비밀값 교체

대상 편집에는 현재 서버·계정 이름·범위·연결된 비밀값 이름만 표시한다. 기존 비밀값 입력란은 비워 둔다. `인증 갱신`을 눌러 새 값을 입력하고 테스트한 후 교체하도록 유도한다. 테스트 실패 시 기존 값은 유지하고 실패 원인을 보여준다. 사용자가 테스트 없이 교체를 선택하는 경우에는 해당 값이 아직 검증되지 않았음을 분명히 표시한다.

비밀값을 삭제할 때 연결된 대상 이름을 먼저 보여준다. 사용 중인 비밀값은 기본적으로 바로 삭제하지 않고, 대상을 다른 값으로 바꾸거나 참조를 해제하게 한다. 삭제 확인에는 친숙한 이름을 표시하고 원래 비밀값은 노출하지 않는다.

HTTP 422 검증 화면은 유일한 오류 입력에 `autofocus`를 주어 수정 위치로 바로 이동시키고, `aria-invalid`와 `aria-describedby`로 오류를 연결한다. Go rendered-response tests는 속성 계약을 확인했으나 실제 Chrome POST 뒤 포커스는 아직 확인하지 않았다.

같은 날짜의 browserless regression은 language-select change handler가 Korean 선택에 대해 `lah_lang=ko; Path=/; SameSite=Strict` cookie와 `lah-lang=ko` local-storage 값을 쓰는지 확인한다. 별도 `newLocalUIHandler` integration test는 exact same-origin Host/Origin 및 en/ko locale cookie를 production security middleware를 거쳐 Dashboard 422 화면까지 보낸다. 이 테스트는 제품 경로 조합과 고정 응답을 확인하지만 실제 browser submit, browser focus 이동, 확대율 검증은 대체하지 않는다.

### 연결 실패와 진단

테스트는 다음처럼 결과를 나눠 설명한다: 주소 도달, TLS, 인증, 권한/범위, 서비스 API 응답. 사용자에게 HTTP 상태 코드와 안전한 해결 안내를 제공한다.

현재 코드의 일회성 안내는 주소/전송 실패, request timeout, HTTP 408, 401, 403, redirect·404, 429, 기타 HTTP 실패를 구분한다. GitHub 403은 문서화된 rate-limit 응답 신호가 단일 값으로 있을 때 rate limit으로 분류하고, 다른 403은 접근 거부로 안내한다. Timeout 안내는 deadline/network timeout/408을 고정 문구로 설명한다. 아래 표의 TLS 단독 분류, 모든 HTTP 코드 표시, 마스킹된 항목 수 표시는 목표 UX이며 이번 Windows 화면 검증에서 확인된 동작이 아니다. 404는 endpoint·리소스 부재와 숨겨진 접근 거부를 구별할 수 없다고 안내한다.

| 결과 예 | 안내 |
|---|---|
| 주소를 찾지 못함/시간 초과 | 주소·VPN·네트워크 연결을 확인하라고 안내 |
| TLS 인증서 오류 | 인증서/프록시 문제 가능성을 알리고 인증서 검증을 끄는 우회는 기본 제공하지 않음 |
| 401 | 인증값이 없거나 거부됨. 비밀값 이름과 서비스 계정 입력을 다시 확인 |
| 403 | 인증은 되었지만 권한 또는 선택 범위가 부족함 |
| API 경로/응답 형식 불일치 | 주소의 기본 경로와 서비스 버전·프록시 경로를 점검하도록 안내 |

오류 화면은 다음 행동을 먼저 말한다. 토큰·비밀번호·Authorization 헤더·전체 요청/응답 본문은 출력하지 않는다. 주소에 자격정보가 포함되면 제거한다. 서비스가 돌려준 로그는 민감값 마스킹 후 일부만 보여주며, 마스킹된 항목 수를 알린다. “연결 성공”은 그 시점의 테스트 결과이지 이후 가용성을 보증하는 문구가 아니다.

### AI 에이전트 작업

AI 도구 화면에서 각 클라이언트의 등록 상태를 `등록됨`, `설정 필요`, `재시작 필요`, `확인 불가`로 구분한다. 확인하지 않은 상태를 성공으로 표시하지 않는다. 등록 전에는 어떤 로컬 설정을 바꾸는지 클라이언트 이름과 함께 표시한다.

현재 UI에는 Codex CLI·Claude Code CLI·Gemini CLI의 공식 설치 링크와 수동 stdio 등록·상태 확인 예시를 접을 수 있는 안내 패널이 있다. 이미 열린 세션에서 서버가 보이지 않으면 Codex는 새 세션, Claude Code는 `/mcp`에서 상태 확인 후 `claude mcp get local-agent-harness` 실행, 계속 실패하면 새 CLI 세션 시작을 안내한다. Gemini는 `/mcp reload`와 신뢰된 폴더 상태 확인을 안내한다. 각 CLI에는 서로 독립된 세 가지 선택형 사용자 보고 체크인이 있다. 사용자는 등록 명령 뒤 저장된 서버 목록, 실행 중인 CLI 세션의 MCP 도구, passive catalog 응답을 각각 확인했다고 표시할 수 있다. 상태 문구는 사용자의 보고이며 앱이 클라이언트 설정을 읽거나 연결을 검증했다는 뜻이 아니다. 체크는 현재 페이지 메모리에만 있고 새로고침하면 초기화되며, 각 CLI별 초기화 버튼은 해당 CLI의 세 보고를 지운다.

에이전트가 허용된 작업을 호출하면 대상 이름·요청 작업·범위를 검증한 뒤 실행한다. 응답은 필요한 필드만 선택하고 민감값을 마스킹한 후 MCP에 반환한다. 로그·오류도 같은 출구 필터를 지난다. 기본 진단에는 비밀값, 환경변수 덤프, 전체 헤더, 전체 응답 본문을 넣지 않는다. 사용자가 설정한 권한 밖의 요청은 대상·허용 범위를 제시하며 거부한다.

Dashboard에는 등록된 서비스 묶음·환경에서 Deployment 상태, 이벤트와 Pod 목록을 묶어 읽는 `dashboard_deployment_diagnosis` MCP 도구와 로컬 UI 진단 패널이 있다. 선택기에는 활성 Dashboard 매핑만 포함한다. namespace와 Deployment를 모두 지정한 활성 매핑이 없으면 선택기와 실행 폼을 표시하지 않고, 완전한 매핑과 권한 있는 활성 대상을 로컬 설정에서 준비하라는 안내를 보여준다. 사용자는 저장된 매핑만 선택하고 버튼을 눌러 최대 5회의 제한된 GET을 실행한다. 화면은 단계별 부분 결과·고정 오류 안내·결과 축소 사실을 표시하며, HTTP 5xx에는 Dashboard 가용 상태와 나중 재시도를 안내한다. 조회 성공을 Deployment 정상 판정으로 표현하지 않는다. 이 진단은 저장된 자격 증명을 읽을 수 있지만 설정·연결 이력을 바꾸지 않는다. 결과에 표시된 Pod/container마다 UI 버튼으로 최근 로그를 별도 요청할 수 있으며, 이 요청도 매핑과 현재 inventory를 다시 검사한다. 서비스 묶음·환경 선택을 바꾸면 이전 결과와 화면에 남은 상태를 지우고 현재 언어로 범위 변경 안내를 보여준다. 요청 전 선택 변경은 안내를 띄우지 않고, 선택만으로 진단 요청을 보내지 않는다. MCP에서는 같은 경계의 별도 로그 도구를 제공한다. 로그에 애플리케이션 데이터가 있을 수 있으므로 공유 전 검토한다. 자동 실행 마법사나 실제 Dashboard 호환 확인은 아니다.

### Jenkins trigger 확인

대상 설정에서 사용자가 “이 정확한 job은 비운영이며 호출별 확인 없이 trigger를 허용한다”는 체크를 직접 선택해야만 사전 허용한다. 기본은 사전 허용 해제다. 체크하지 않은 대상은 trigger 호출마다 로컬 loopback 브라우저에서 한 번 확인한다. 화면에는 등록 대상 이름, proxy/context path를 포함한 정확한 Jenkins 주소, 사용자가 정한 environment label, 고정 job path를 보여준다. label만 보고 운영 여부를 판단하지 않는다. 거부·취소·시간 초과·확인 화면을 열지 못한 경우나 확인 후 대상이 바뀐 경우에는 trigger를 보내지 않는다.

## 좋은 기본값과 휴먼 에러 방지

- 한 번에 알아볼 수 있는 대상 이름, 서비스 종류, 범위, 테스트 상태를 목록에 표시한다. 대상별로 “마지막 테스트 시각”을 함께 보여 오래된 성공 상태를 현재 연결로 오해하지 않게 한다.
- 입력을 지우기 전에 저장 여부를 확인한다. 연결 테스트 실패, 화면 다시 로드, 클라이언트 미등록이 기존 설정을 삭제하지 않는다.
- 주소·계정·권한·비밀값을 서로 다른 항목으로 보여준다. 계정 이름과 비밀값 이름은 다시 확인할 수 있지만 비밀값 자체는 재표시하지 않는다.
- 초깃값은 서비스별 안전한 읽기 범위다. 모든 네임스페이스/모든 저장소/모든 job 권한을 묵시적으로 선택하지 않는다.
- `저장`, `연결 테스트`, `AI 클라이언트 등록`은 각각 결과가 다른 동작으로 명명한다. 성공 상태와 실패 상태는 색만으로 전달하지 않는다.
- 대상 이름이 겹치거나 주소 형식이 틀리면 저장 전에 해당 입력 근처에서 이유를 보여준다.
- 설정 변경이 AI 클라이언트 재시작을 요구하면 영향을 받는 클라이언트만 표시한다. 재시작 전까지 현재 설정과 적용 예정 상태를 구분한다.
- 비밀값 처리로 모든 위험이 없어졌다고 표현하지 않는다. 같은 Windows 사용자 권한으로 실행되는 다른 프로세스에 대한 격리 수준은 UI가 보장한다고 약속하지 않는다.

### 기존 환경 가져오기

Git config와 Runbook의 흐름은 **파일 선택 → 후보 미리보기 → 기존 대상 선택 → 서비스 묶음 저장 → 연결 테스트**다. 사용자는 Git config `config` 파일이나 `.md`/`.txt` Runbook 파일 하나를 직접 선택한다. 확장자 검사는 대소문자를 구분하지 않는다. 별도 SSH config 미리보기는 사용자가 선택한 이름 `config`에서 리터럴 alias 목록만 표시하며 등록 대상 선택이나 저장으로 이어지지 않는다. 기존 설정 preview는 Local Agent Harness가 만든 `.json` 파일 하나를 선택해 버전과 항목 개수만 확인한다. 별도의 schema-neutral JSON preview는 사용자가 선택한 JSON에서 키가 아닌 문자열 값 전체만 검사해 Git 저장소 후보를 찾는다. 대화 schema나 대화 개수를 제공한다고 표시하지 않으며 저장소명·낮은 신뢰도·활성 대상 exact-match 여부만 반환한다. 브라우저가 실제 파일 경로를 앱에 공개하지 않아 파일이 저장된 실제 경로를 확인할 수 없다. Git·Runbook·SSH 파일 상한은 64 KiB, multipart 요청 상한은 72 KiB, 미리보기 JSON 응답 상한은 64 KiB다. settings JSON은 1 MiB·1 MiB+8 KiB·8 KiB이고 JSON remote preview는 1 MiB·1 MiB+8 KiB·64 KiB다.

Git 미리보기는 remote 별칭과 repository를 보여주고, Runbook 미리보기는 `lah:repository <Git remote URL>` 지시자에서 뽑은 repository와 중복 횟수를 보여준다. 두 흐름 모두 출처 경로를 검증하지 못한다는 점, 확신도, 확인이 필요한 Jenkins·Harbor·Dashboard 매핑 및 권한을 설명한다. Runbook은 `.md` 또는 `.txt`에서 최대 512줄·32개 고유 참조를 처리하며 일반 문서 텍스트와 임의 URL은 무시한다. 원격 URL 원문은 표시하지 않는다. 등록된 활성 GitHub 대상의 origin과 repository가 정확히 일치할 때만 선택 후보가 된다. 후보당 최대 8개 매치를 보여주며, 더 있으면 추가 매치가 있음을 알린다. 여러 매치는 낮은 확신도로 표시한다. 선택 버튼은 서비스 묶음 폼의 기존 대상 체크를 바꿀 뿐이며, 사용자가 묶음을 저장하기 전까지 설정에 반영되지 않는다. 연결 테스트는 별도로 실행한다.
Git alias·repository·매치된 대상 이름에 알려진 토큰 패턴이 있으면 해당 문자열은 `[REDACTED]`로 표시될 수 있다. exact match는 원래 값으로 계산한다. 이 표시는 알려진 패턴 필터이며 모든 비밀정보를 찾아낸다는 보장은 아니다.

미리보기는 설정을 저장하거나 Credential Manager 비밀값을 읽거나 만들지 않는다. Git config·Runbook·JSON remote preview는 활성 대상 exact-match 표시를 위해 설정을 읽기만 하며 SSH와 settings count preview는 설정을 읽지 않는다. parser는 허용된 remote URL 형식만 검사하며 임의 파일을 열거나 외부 네트워크, Git·셸·SSH를 실행하지 않는다. JSON remote preview는 키·부분문자열을 검색하지 않고 전체 문자열 값만 읽고, 4 KiB 초과 값·잘못된 문서·32개 초과 후보를 안전하게 건너뛰거나 거부한다. 모든 후보는 낮은 신뢰도이며 활성 대상 일치도 수동 검토 안내로만 보인다. SSH preview는 단순 리터럴 `Host` alias만 반환하며 `HostName`은 구문만 확인하고 결과에 넣지 않는다. 계정·키·proxy 값과 alias에 연결된 repository/target은 표시하거나 추정하지 않는다. `Include`와 `Match`는 거부하며 나머지 directive는 해석하지 않는다. 설정 JSON preview는 v4/v5/v6/v7을 허용하고 v5~v7은 Python 작업 수를 포함한다. v6/v7 secret mapping과 v7 fingerprint 필드는 strict allowlist·값 검증에만 쓰며 count-only 응답은 작업 수 외 세부를 포함하지 않고 Credential Manager에도 접근하지 않는다. 중복·변형·알 수 없는 키와 `null`을 거부한다. 이 화면은 항목 수만 표시하며 이름, URL, ID, 사용자명, credential reference, 승인 정보, 연결 이력, 원문은 노출하지 않는다. 지정된 대화 JSON schema/count parser는 미구현이다. 다른 클라이언트의 대화 전체나 `.env`·인증 파일 원문은 자동으로 읽지 않는다.

### 서비스 묶음과 카탈로그

### 등록 Python 작업

등록 패널은 `.exe`와 고정 `.py` 경로를 받고, 선택적으로 환경 변수 이름과 비밀값을 연결한다. 설정에는 이름과 Credential Manager reference만 저장한다. 저장된 값을 다시 표시하지 않으며 새 값이 비어 있으면 기존 연결을 유지하고 별도 체크로 연결을 지울 수 있다. 환경 변수 이름은 예약된 시스템/Python 이름을 거부하는 제한된 ASCII 형식이며 secret은 4096 byte 이하의 비어 있지 않은 UTF-8, NUL 없음만 허용한다. UI는 저장할 `.exe`가 Python인지 확인하지 않는다고 설명하고, 새 파일·경로 변경·감지된 drift를 저장하려면 명시적인 파일 검토 확인을 받는다. 확인 후 `.exe`와 `.py`의 SHA-256 및 크기를 pin한다. 실행 전·승인 후·child 시작 직전 재검사에서 drift, 누락, 읽기 실패 또는 `.exe` 256 MiB·`.py` 16 MiB 상한 초과가 발견되면 실행하지 않는다. 마지막 검사 뒤 OS가 파일을 여는 순간까지 교체 race-free를 보장하지는 않는다. 저장할 때 현재 Windows 사용자 권한과 실행별 일회성 로컬 브라우저 승인이 필요하다는 동의를 받는다. MCP 호출은 매번 task 이름과 설정된 환경 변수 이름만 보여주는 승인 페이지를 열며 승인 전 저장 경로의 파일 지문을 검사하지만 승인 화면에는 경로를 표시하지 않는다. 거부·취소·시간 초과·브라우저 열기 실패면 실행되지 않는다. 승인 후 현재 task 설정과 파일을 다시 확인하고 해당 task의 참조만 읽어 작업 루트 프로세스 환경에 전달한다. MCP 인자에는 임의 환경값이나 비밀 원문을 넣을 수 없다. passive MCP 카탈로그는 설정만 읽고 경로·참조·환경 변수명이나 파일 존재 여부를 내보내지 않는다. Windows에서는 rooted drive-letter 형식만 허용하고 UNC·DOS/NT device namespace 경로를 거부하지만, 매핑된 네트워크 드라이브인지는 확인하지 못한다. 실행은 로컬 파일이나 네트워크에 영향을 줄 수 있고 샌드박스가 아니다. Windows 10 이상에서는 프로세스 생성 시 루트를 Job Object에 포함해 일반 CreateProcess 후손을 정리하며, 동시 2개·30초 제한은 작업 트리 전체에 적용한다. 정리를 확인하지 못하면 앱 재시작 전까지 추가 실행을 차단한다. Win32_Process.Create 등 Job 밖에서 생성한 프로세스는 포함되지 않는다. 비밀값은 루트 환경에 전달되고 후손이 물려받을 수 있다. 비-Windows fallback은 직접 자식만 기다린다. stdout/stderr는 현재 MCP 호출 결과에만 스트림별 최대 8 KiB로 표시하며 설정·로그·실행 이력에는 저장하지 않는다. 상한을 넘긴 원문 stream은 통째로 생략하고 잘림을 표시한다. UTF-8·NUL 검사나 best-effort secret/pattern 정리에 실패하면 출력 전체를 생략한다. 이 정리는 모든 비밀 제거를 보장하지 않는다. 메모리 지우기는 최선 노력이며 완전한 비밀 제거를 보장하지 않는다. 이 안내는 English와 Korean translation map에 포함한다. 실제 Credential Manager 왕복, Python runtime과 실제 task 성공은 확인하지 않았고 실행별 승인 페이지도 synthetic HTTP client 테스트만 거쳤다.

### GitHub Enterprise 및 Dashboard 주소

GitHub Enterprise REST는 입력한 `https://HOSTNAME` origin의 `/api/v3/...` 경로만 사용하고 Bearer PAT를 첫 인증 경로로 둔다. `gh auth token --hostname HOSTNAME` 연동은 token 전달 경계를 검증한 뒤 고려할 후속 후보이며, SSH는 Git 전송에만 사용한다. Dashboard에는 사용자가 기본 주소를 입력한다. 설계 기준은 공식 `kubernetes-dashboard` Helm chart release `7.14.0`과 그 chart가 지정한 web/auth/api 컴포넌트다. 회사 설치 버전과 프록시 prefix는 미검증으로 표시하며 확인 전에는 호환됐다고 표시하지 않는다.

## 접근성과 시각 QA

UI를 바꿀 때마다 실제 Windows 11 브라우저에서 렌더링된 화면으로 다음 흐름을 확인한다. DOM 스냅샷이나 컴포넌트 테스트만으로 시각 QA를 통과했다고 하지 않는다.

1. 처음 실행 빈 화면부터 Jenkins·Harbor·GitHub·Dashboard 대상을 각각 추가하고 목록에서 다시 편집한다.
2. 비밀값을 저장·선택·교체·삭제하며 화면·브라우저 오류·앱 로그·MCP 응답에 원문이 나타나지 않는지 canary 값으로 확인한다.
3. 정상 연결, 잘못된 주소, 401, 403, 시간 초과를 재현해 메시지와 다음 행동을 확인한다.
4. 키보드만으로 주요 흐름을 완료하고, 브라우저 확대와 좁은 창에서 화면 잘림·겹침을 확인한다.
5. Codex·Claude·Gemini 각각의 등록 여부, 재시작 안내, MCP 연결 상태를 실제 클라이언트에서 대조한다.

시각 QA 결과는 사용한 브라우저, Windows 버전, 창 크기/확대율, 완료한 시나리오, 발견된 문제를 짧게 기록한다. 미실행 시나리오는 통과로 간주하지 않는다.
