# Desktop MCP onboarding compatibility (2026-10-11)

This note separates published product capability from this repository's current adapters and from actual first-run evidence. Official product guidance was checked on 2026-10-11. It does not verify the installed ChatGPT or Claude app version, workspace policy, company Dashboard authentication, or a successful call from this machine.

OpenAI documents a separate hosted ChatGPT route: ChatGPT web uses remote MCP-backed tools supplied by plugins and does not read local Codex configuration. A local stdio executable should not be described as a ChatGPT web connector or as a remote MCP server. The ChatGPT desktop steps above refer to its local Codex/MCP host and same-host sharing.

Anthropic also separates local desktop extensions from remote connectors. Remote custom connectors are reached from Anthropic's cloud infrastructure and require the MCP server to be publicly reachable; a local stdio executable is not that route. The current remote connector guide lists Free, Pro, Max, Team, and Enterprise availability, with one custom connector for Free accounts. Team/Enterprise organization controls and Windows enterprise policies can still restrict local extensions or local development MCP.

## Repository facts

- The registered client IDs are exactly `codex`, `claude`, and `gemini` in [client_registration.go](../../client_registration.go). Registration specs in [runtime_clients_ui.go](../../runtime_clients_ui.go) are fixed to stdio, the current executable, the single argument `--mcp`, and user scope.
- The Claude adapter in [client_claude.go](../../client_claude.go) looks for the `claude` executable and reads/writes `~/.claude.json`. The repository's [CLI setup guide](../../CLIENT_SETUP.md) labels this **Claude Code CLI** and explicitly says this is not Claude Desktop setup.
- The Codex adapter in [client_codex.go](../../client_codex.go) looks for the `codex` executable and edits `~/.codex/config.toml`, or the configured `CODEX_HOME` path. Official OpenAI guidance says the desktop app shares MCP configuration with Codex CLI and the IDE extension for the same Codex host. That lets a Codex adapter registration be visible to Desktop, but does not make the adapter Desktop-aware or prove Desktop loaded or called it.
- The UI and status model keep `Connection` and `ToolCall` unverified. A saved/observed client config, a healthy local endpoint, or a successful service connection test does not prove that an AI desktop app called an MCP tool.
- Claude's current Desktop onboarding article presents local Desktop Extensions and `.mcpb`; a separate current remote-connector article names `claude_desktop_config.json` as a distinct local mechanism. The published local setup steps reviewed here use `.mcpb` and do not provide a complete manual JSON recipe for registering this executable in Claude Desktop, so this note does not invent one.

## Safe manual verification

For ChatGPT Desktop, first confirm that the installed Windows app exposes **Settings → MCP servers**. If available, use the official UI with the absolute executable path and `--mcp`, then save and restart. In the target desktop session, use `/mcp` to confirm the server and its tools appear. Ask for a local catalog call such as `registered_targets` or `registered_service_bundles`, and inspect the returned catalog. The catalog call does not test a service credential or the company's Dashboard authentication.

For Claude Desktop, review the local unsigned preview package at `output/claude-desktop/local-agent-harness-0.1.0-ux.1-windows-amd64.mcpb` and install it through **Settings → Extensions** if you choose to verify the client integration. Confirm it appears with its tools under **+ → Connectors** and inspect Developer settings/logs if startup fails. The package is not shipped, and no installation or app-call evidence is recorded here; manual `claude_desktop_config.json` editing is therefore not a supported product instruction in this note.

For Codex CLI, use the existing executable registration example in [CLIENT_SETUP.md](../../CLIENT_SETUP.md). Verify `codex mcp list`, start a fresh Codex session, inspect `/mcp`, then call a local catalog tool and inspect its result. For ChatGPT Desktop using the same Codex host, perform the `/mcp` and catalog checks again inside the desktop app; CLI results alone are not desktop evidence.

Keep the evidence in separate steps. Record the exact product and version, Windows user, date, transport, and executable path. Then record whether (1) the client accepted the registration, (2) the target app displayed the server, (3) it displayed the tools, (4) a local catalog call returned a response, and (5) an explicitly selected external read succeeded. Only step 5 tests the external target and its credentials; it can cause an external request and may write local connection history, so choose the target and permission deliberately. Dashboard token/auth behavior remains unverified and is outside this compatibility research.

Do not derive install, connection, tool-call, or first-read success from a config file or UI checkbox. The current product has no per-client Desktop call receipt. Its first-read instrumentation is not implemented; any page-level check-in is a user report and must not be labeled `mcp_observed` or substituted for an app-observed MCP result.

## Official sources checked 2026-10-11

- OpenAI, [Model Context Protocol](https://learn.chatgpt.com/docs/extend/mcp?site_variant=chatgpt): desktop and Codex clients share configuration for the same Codex host; local STDIO is supported; direct Desktop setup and `/mcp` steps; hosted ChatGPT web uses plugins/remote MCP and does not read local Codex configuration.
- Anthropic, [Getting Started with Local MCP Servers on Claude Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop): local `.mcpb` install steps, binary-server support, status/log locations, and Windows permission/policy considerations.
- Anthropic, [When to use desktop and web connectors](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors): local extensions versus remote connectors and their available surfaces.
- Anthropic, [Get started with custom connectors using remote MCP](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp): current plan availability and requirement that remote MCP servers be reachable from Anthropic's cloud.
- Anthropic-linked MCPB project, [MCP Bundles](https://github.com/modelcontextprotocol/mcpb): `.mcpb` package format and binary bundle support for Windows.
- Anthropic, [Enterprise configuration for Claude Desktop](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop): desktop-extension and local-development-MCP policy controls.

OpenAI's desktop menu and same-host statement describe product capability, not account rollout or this machine's app version. Check that the menu exists on the installed client before presenting the path as available to that user. MCPB CLI validation of the local package does not establish installation, launch, tool visibility, a successful Claude Desktop MCP call, credential behavior, or a Dashboard read.
