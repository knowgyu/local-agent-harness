# 사용자 수용 체크리스트

이 체크리스트는 Local Agent Harness의 로컬 UI와 선택한 MCP 흐름을 직접 확인하는 기록입니다. 개인 정보, 비밀값, 실제 주소·호스트, 고객 또는 회사 데이터를 적지 마세요. 실제 회사 서비스나 운영 데이터를 사용하지 않습니다. 비운영 테스트 환경을 쓸 수 없으면 해당 항목을 `미확인`으로 남기세요.

각 항목은 `통과`, `실패`, `미확인` 중 하나로 기록합니다. 설정을 저장했다는 사실은 연결 성공의 증거가 아니며, 과거 연결 결과도 현재 상태를 보증하지 않습니다.

## 다운로드와 첫 실행

- [ ] `local-agent-harness-v0.1.0-rc.2-windows-amd64.zip`의 SHA-256이 `ce674bbb40934e0f5d33b23ea290ec6be3a719bed3efeb1c41d071024112c025`이며 함께 게시된 `SHA256SUMS.txt`의 값과 일치한다.
- [ ] ZIP 내부 `manifest.json`의 `package_version`이 `v0.1.0-rc.2`이고 파일 9개가 들어 있는지 확인한 뒤, 전체 압축 해제해 패키지 폴더에서 설치 스크립트를 실행했다.
- [ ] 앱을 열고 로컬 UI가 loopback 주소에서 표시되는 것을 확인했다.
- [ ] 첫 화면의 기본 언어가 한국어이고, 언어 선택을 통해 영어로 전환할 수 있음을 확인했다.
- [ ] `/readiness`를 열어 등록 대상, 이력, 클라이언트 상태가 각자 구분되어 표시되는지 확인했다. `미확인`은 성공이나 비어 있음으로 해석하지 않는다.

## 설정과 데이터 경계

- [ ] 설정 화면과 운영 기능을 각각 찾아 필요한 항목을 확인했다. 화면을 열기만 해도 실제 서비스에 연결하거나 작업을 실행하지 않는지 확인했다.
- [ ] 비운영 시험을 수행할 경우, 이름 있는 연결 대상과 허용 작업만 등록했다. `registered_targets` 결과에 등록한 이름과 허용 작업이 표시되는지 확인했다.
- [ ] 실제 MCP 호출을 할 수 있는 클라이언트가 있다면 `registered_targets`를 호출했다. 등록 화면이나 클라이언트 설정 목록만 확인한 경우에는 이 항목을 미확인으로 남겼다.
- [ ] 비밀값을 입력·저장하는 경우 값이 저장 후 화면에 다시 나타나지 않고 설정에는 참조만 남는지 확인했다. 실제 자격 증명 대신 시험용 값을 사용했다.
- [ ] 사용자 환경 변수 기능을 확인하는 경우 기존 변수 값을 교체하지 말고, 겹치지 않는 시험용 이름과 값을 사용했다. 값은 같은 Windows 계정의 다른 프로그램에서도 읽을 수 있음을 확인한 뒤 시험 변수를 삭제했다. 값을 화면 캡처·로그·메모에 남기지 않았다.

## 주요 기능별 확인

- [ ] `연결 그룹(서비스 묶음)`에서 비운영 시험용 기존 대상과 GitHub 저장소, Jenkins 작업, Harbor 이미지, Dashboard 네임스페이스·Deployment를 환경별로 연결했다. 각 매핑이 맞고, 그룹을 만들거나 바꿔도 연결 대상의 허용 작업 범위가 넓어지지 않는지 확인했다.
- [ ] 시험용 비밀값을 교체한 뒤 입력란이 비고, 해당 값을 참조하는 저장된 연결 전체에 새 값이 적용되는지 확인했다. 이전 값 정리가 `cleanup_pending`(이전 자격 증명 정리 대기)이면 화면의 정리 대기 상태와 `정리 재시도`를 확인하고, 재시도 후 완료 상태인지 확인했다. 정리 상태를 확인할 수 없으면 이전 값이 삭제됐다고 가정하지 않았다.
- [ ] `/readiness`에서 클라이언트 설치·버전·저장된 등록 정보를 확인했다. `AI 앱 연결` 화면의 등록 결과, 열린 클라이언트 세션에서 서버·도구를 본 사실, 실제 `registered_targets` 호출을 각각 구분해 기록했다. 사용할 클라이언트가 없으면 실제 호출은 미확인으로 남겼다.
- [ ] 격리된 설정에서 AI 설정 초안을 검토했다. 검토 화면의 대상·환경 매핑·허용 범위·권한 변화를 읽고, 검토만으로 설정이 바뀌지 않는지 확인한 뒤 직접 승인했다. 초안 작성 뒤 설정 버전이 바뀌면 오래된 초안 승인이 거부되고 최신 설정을 덮어쓰지 않는지 확인했다. 무변경 검사는 이미 v9인 설정에서 수행했으며, v8에서 시작하면 화면 진입 전 마이그레이션으로 설정이 바뀔 수 있어 별도 범위로 남겼다.
- [ ] JavaScript를 끈 브라우저에서 홈과 `/readiness`의 정적 안내를 확인했다. 준비도·클라이언트 조회나 설정 변경이 자동 실행되지 않는지 확인했다. 홈 일부 문구는 영어로 남을 수 있고 링크·키보드 활성화는 별도 확인 항목으로 구분했다. JavaScript를 쓰는 사용자 확인 표시는 현재 브라우저의 앱 출처에만 남고 확인 시각과 설정 버전만 기록하며, 설정 버전이 바뀌면 지워지는지 확인했다. 저장소 사용이 제한되면 세션 또는 현재 탭에만 남고 앱 설정이나 MCP·클라이언트 설정에는 저장되지 않는다.

## 연결과 운영 기능

- [ ] 외부 연결을 점검해야 한다면 승인된 비운영 테스트 대상에서만 수행했다. 실제 주소·호스트·응답 본문은 기록하지 않았다.
- [ ] Dashboard 진단은 접근 가능한 Dashboard의 실제 REST 경로와 인증 흐름이 확인된 경우에만 진행했다. 직접 Kubernetes API 연결로 대체하지 않았다. 대상 버전이나 경로를 확인할 수 없으면 미확인으로 남겼다.
- [ ] 사용한 경우, 목록·조회 전용 작업만 골라 직접 호출했다. Jenkins 작업 실행, SSH 명령, Python 작업 실행 등 상태를 변경하거나 프로세스를 실행하는 동작은 수용 시험에서 수행하지 않았다.
- [ ] 오류나 응답에 비밀값이 보이지 않는지 확인했다. 필터링은 모든 비밀 형태를 찾아낸다는 보장이 아니므로 민감한 응답을 시험 자료로 붙여 넣지 않았다.

## 업데이트와 제거

- [ ] 별도 시험 설치에서 실행 중인 앱을 종료한 뒤 업데이트 절차를 실행했다. 사용 중인 설치가 있다면 이 확인을 건너뛰고 미확인으로 남겼다.
- [ ] 별도 시험 설치에서 제거 절차를 실행했고, 예상하지 않은 파일·사용자 데이터 삭제가 없었는지 확인했다.
- [ ] 복구 오류가 발생한 경우 설치 폴더와 상태 파일을 보존하고 추가 조작을 중단했다.
