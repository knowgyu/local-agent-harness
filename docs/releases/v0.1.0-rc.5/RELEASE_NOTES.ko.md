# v0.1.0-rc.5

Windows x64용 사전 공개 후보입니다. RC4를 기준으로 에이전트가 설정 절차를 읽고 진행 상태를 확인하는 흐름을 추가했습니다.

- `setup_status`: 기존 준비 상태와 같은 로직으로 대상별 등록·연결 시험·실제 MCP 조회 기록을 반환합니다. 기본 호출은 서비스 접속이나 클라이언트 설정 검사를 하지 않습니다.
- `lah://guides/agent-setup`: 설치한 MCP 서버에서 간결한 영어 설정 안내를 제공합니다. 저장소와 별도 릴리스 첨부 파일에서도 같은 안내를 읽을 수 있습니다.
- 준비 상태 화면에서 대상별 조회 기록과 다음 행동을 표시합니다. 한 대상의 성공을 다른 대상의 성공으로 표시하지 않습니다.
- 조회 증거는 현재 대상·권한·매핑과 일치하는 정의만 인정합니다. 최근 256개 정의의 기록을 보관하며, 한도에 걸려 없는 증거는 미확인으로 표시합니다.
- 지원되지 않는 HTTP 클라이언트 설정과 혼동되던 새 로그인 자동 시작 버튼을 숨겼습니다. 기존 자동 시작의 해제는 유지합니다.
- 사용하지 않는 함수와 오래된 설명을 정리하고, 테스트 전용 도우미를 테스트 파일로 옮겼습니다.

## 설치와 사용

[빠른 시작](START_HERE.ko.md)과 저장소 README를 보세요. 설치 파일 구성은 RC4와 같은 11개이며 설치·업데이트·복구 로직을 별도로 늘리지 않았습니다. `AGENT_SETUP.md`는 ZIP 밖의 별도 릴리스 첨부 파일입니다.

## 검증 결과와 한계

- Codex CLI 0.162.1이 모의 GitHub 대상에서 `github_repository`와 `setup_status`를 실제 호출해 성공했고, 모델 최종 응답도 PASS였습니다. `first_read.state`는 `observed`, `client_attribution`은 `not_observed`입니다.
- Claude Code 2.1.224는 도구 호출 전에 만료된 OAuth로 HTTP 401을 받아 차단됐으며 모델은 실행되지 않았습니다. 두 클라이언트용 SDK 프로토콜 fixture는 통과했지만 fixture만으로 실제 Claude Code 호출을 입증하지 않습니다.
- Windows 네이티브 Go 전체 테스트는 종료 코드 0으로 34.82초, `go vet`은 종료 코드 0으로 0.99초에 완료했습니다.
- Portable ZIP 빌드는 20.65초에 통과했습니다. 디버그 정보를 뺀 EXE 두 개의 바이트가 일치했고, ZIP 구성·개인정보 검사에서 11개 파일 구성을 확인했습니다.
- 고정한 Claude Desktop MCPB 2.1.2의 validate·pack·info는 종료 코드 0으로 13.19초에 완료했습니다. MCPB에는 `manifest.json`과 서버 실행 파일만 들어 있고, 실행 파일의 바이트가 ZIP과 일치합니다.
- 분리된 환경에서 최종 패키지 EXE를 stdio로 확인했습니다. protocol 2025-11-25와 23개 도구를 확인했고, 상태 조회·안내 리소스가 정상 응답했으며 안내 바이트도 일치했습니다. 상태 조회 중 파일 변경은 없었고 잘못된 인수는 거부됐습니다.
- Windows PowerShell 5.1과 PowerShell 7.6.7에서 경로 보호·중단 복구 검사와 배포 ZIP 그대로의 설치·업데이트·제거를 합계 10/10 흐름으로 확인했습니다. 실제 GitHub Enterprise, Jenkins, Dashboard 연결과 Credential Manager의 실제 저장·삭제는 검증하지 않았습니다.

MCP 읽기 영수증은 읽기가 발생했다는 증거이며 호출한 CLI의 신원을 증명하지 않습니다. 상세 테스트 및 패키지 근거는 [검증 요약](VALIDATION_SUMMARY.ko.md)을 참조하세요.
