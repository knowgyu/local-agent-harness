## 설치기 검증 범위

모든 설치기 검사는 작업 전용 합성 경로에서 실행했습니다. 실제 설치 위치·Credential Manager·회사 서비스는 건드리지 않았습니다.

| 검사 | 각 PowerShell에서 확인한 범위 | 두 런타임 결과 |
|---|---|---|
| 루트 생성 경로의 reparse 거부 | 시나리오 1개 | 2회 통과 |
| 루트 디렉터리 잠금 | 루트·바로 위 경로의 이름 변경 차단, 표식 보존 | 2회 통과 |
| 중단 복구 | 9개 사례 | 18/18 |
| RC3 중단 저널 호환성 | 3개 사례 | 6/6 |
| 배포 RC5 ZIP 그대로 설치·업데이트·제거 | 11개 파일과 설치 기록 일치, 제거 후 관리 파일 부재, 별도 사용자 표식 보존 | 2회 통과 |

호환성 스크립트의 `RC4PackageRoot` 등 기존 매개변수에는 이번 RC5 ZIP과 그 해시를 전달했습니다. 검사 대상은 RC3에서 현재 RC5로 이어지는 합성 복구이며 RC4 ZIP을 시험한 결과가 아닙니다. 기존 RC4의 68/68 결과를 재사용하지 않았습니다.

추가로 README 내용을 바꾼 합성 패키지의 설치·실제 파일 교체·제거도 두 런타임에서 통과했습니다. 초기 시험 파일이 체크섬 구분 공백을 한 칸으로 잘못 생성한 경우는 설치기가 거부했고, 요구 형식인 두 칸으로 수정한 뒤 정상 통과했습니다. 제품 코드는 수정하지 않았습니다.

## 실제 CLI와 모의 서비스

- **Codex CLI 0.162.1:** WSL 클라이언트에서 Windows 테스트용 MCP 서버를 시작해 `github_repository`와 `setup_status`를 실제 호출했습니다. 서버는 제품과 같은 MCP 구현에 메모리 자격 증명과 모의 HTTP 전송을 사용했습니다. 모의 GitHub 읽기가 성공했고 `targets[].first_read.state=observed`, `client_attribution=not_observed`를 확인했습니다. 마지막 모델 응답도 PASS였습니다. 이 시험은 최종 배포 EXE의 실제 GitHub 연결이나 Windows용 Codex 등록 검증이 아닙니다.
- **Claude Code 2.1.224:** 같은 격리 모의 검증을 시도했으나 만료된 OAuth 토큰으로 HTTP 401을 받아 도구 호출 전에 중단됐습니다. 모델 사용량은 0으로 보고됐습니다. 인증 파일을 읽거나 자동 갱신하지 않았습니다. 실제 Claude Code MCP 조회는 미확인입니다.
- **두 SDK 프로토콜 fixture:** 안내 조회, 도구 메타데이터, 모의 읽기와 영속 기록 검사를 통과했습니다. fixture에 붙인 클라이언트 이름은 실제 CLI 실행이나 호출자 신원 증명이 아닙니다.

서버 영수증은 현재 대상 정의에 맞는 성공한 MCP 읽기를 기록합니다. 클라이언트 등록·연결 시험과 구분하며, 어떤 CLI가 읽었는지는 서버가 식별하지 않습니다. 별도 CLI 실행 기록이 있을 때만 해당 호스트의 호출 결과를 설명할 수 있습니다.

## 별도 확인이 필요한 범위

실제 GitHub Enterprise·Jenkins·Harbor·Dashboard의 인증·권한·TLS·VPN·proxy, Windows Credential Manager의 실제 저장·삭제, Windows용 CLI 등록, Claude Code의 로그인 복구 후 실제 MCP 조회, Claude Desktop 설치와 실행은 확인하지 않았습니다. RC5 전체 온보딩의 신규 사용자 시험과 브라우저 시각 검토도 수행하지 않았습니다. RC4의 화면 검토를 RC5 결과로 재사용하지 않습니다.

[사용 확인 체크리스트](USER_ACCEPTANCE_CHECKLIST.md)에서 실제 환경의 성공 여부를 따로 기록하세요.
